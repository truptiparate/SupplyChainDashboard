# Supply chain disruption case-study dashboard

## What this project is

A browsable dashboard of 10 real-world supply chain disruption case studies
(Nokia/Ericsson chip fire, Zara RFID, Tesla vertical integration, Ryanair,
Maersk/NotPetya, Toyota x2, KFC UK, Firestone/Ford, Cisco bullwhip effect).
Source of truth is a hand-authored Excel workbook. This is NOT transactional
data (no SKUs/inventory/orders) — it's qualitative narrative + some numeric
scoring, one sheet per case study.

## Project layout

This is now a real Vite + React project — `npm install`, `npm run dev`,
`npm run build`, not a hand-rolled string-replace script.

```
data/
  source.xlsx         <- the original workbook (replace this when the user sends an update)
scripts/
  extract.py           <- Excel -> JSON extraction engine (label-anchored, see below)
src/
  data/
    cases.json          <- extracted clean data, regenerated by scripts/extract.py
  App.jsx               <- the dashboard component (formerly dashboard_template.jsx —
                           renamed on the Vite migration; imports cases.json directly,
                           no more __CASES_JSON__ placeholder)
  main.jsx              <- React DOM mount point
index.html              <- Vite entry HTML
vite.config.js           <- React plugin + vite-plugin-singlefile (see below)
package.json
```

### Dev workflow

```
npm install       # once, or after dependency changes
npm run dev        # local dev server with HMR at localhost:5173
npm run build       # production build -> dist/index.html
npm run preview      # serve the production build locally to sanity-check it
npm run extract       # re-run the Excel -> JSON extraction (python3 scripts/extract.py data/source.xlsx src/data/cases.json)
```

To rebuild after the Excel changes, just run `npm run extract` — `src/App.jsx`
imports `src/data/cases.json` as an ES module, so Vite picks up the new data
on the next `dev`/`build` automatically. There's no separate "bake the JSON
into the template" step anymore.

### Producing a standalone artifact (e.g. for Claude Artifacts)

`npm run build` uses `vite-plugin-singlefile` (configured in `vite.config.js`),
which inlines all JS/CSS into `dist/index.html` instead of emitting separate
hashed asset files. `cases.json` gets bundled into that inlined JS at build
time — there is no runtime fetch of it. The result is one self-contained HTML
file with no external requests, safe to publish directly as an Artifact.
`dashboard_built.jsx` (the old manually-baked JSX file) no longer exists —
`dist/index.html` from `npm run build` is its replacement and is a strictly
better artifact (actually valid browser JS, not raw JSX requiring an
in-browser transpiler). `dist/` is gitignored — regenerate it with
`npm run build` whenever you need it, don't commit it.

(cases.json as extracted has some cruft like `_second_table_start_col` markers
and `_sheet_name`/`_overall_calculated` fields — `src/App.jsx` doesn't care,
but if you write a new consumer, strip those first.)

## Why the extraction works the way it does (read this before touching extract.py)

Each case sheet (`FIB-001`..`FIB-010`) is a **narrative document, not a table**.
Row positions are NOT fixed and shift per sheet because node counts, decision
counts, and KPI counts vary per case. There is no reliable coordinate system —
only label text is reliable. **Never hardcode a row number.** Every section is
found by searching column B (occasionally other columns) for an anchor label.

### Anchor labels confirmed present in ALL 10 filled sheets (safe to rely on):
`Use case ID`, `Use case Name`, `Industry Verticle`, `Brand & Group`, `Scale`,
`Normal State`, `Baseline Operations (Normal Flow)`, `Normal KPI Conditions`,
`Disruption State 1`, `Disruption details`, `Trigger event`, `Decision No`,
`Action`, `Best when`, `Decisions Impact Summary -`,
`KPI Change Summary - Self Analyses`, `Scenario`,
`Decision Analysis Score - Self Analyses`.

### What legitimately varies per sheet (don't try to force consistency):
- **KPI names** in "Normal KPI Conditions" — e.g. Ryanair tracks "Operating
  margin"/"Load factor", Toyota tracks "Sub-tier supplier visibility". This is
  intentional, case-specific content. Extraction reads these as generic
  label→value pairs, not a fixed field list.
- **Root cause sub-fields** — sometimes one "Root cause details" field,
  sometimes split into "Root cause (proximate)" / "Root cause (structural)" /
  etc. Same generic label→value handling.
- **Number of decision blocks** — most sheets have 2 (`Decision Analysis by
  the Company` = what really happened, `Decision Analysis (Self Analysis)` =
  proposed alternatives). FIB-001 alone has 3 (Nokia / Ericsson / Self) because
  it's a two-company comparison case. Blocks are found by scanning a row for
  ALL cells containing "Decision Analysis", not by assuming a fixed count.
- **Decision block column position** — the second block's starting column
  shifts depending on how many decisions are in the first block. Found by
  label search each time, never a fixed column index.

### Known gotchas already handled in extract.py — don't reintroduce these bugs:
1. The "Normal Flow" step table lives in columns G/H/I (Step/Process/Node) and
   is a SEPARATE, often-longer list than the node descriptions in columns B/C.
   Its header row ("Step") is one row below the "Baseline Operations" section
   title, not the same row.
2. Some sheets (FIB-003, FIB-005, FIB-008) have **no blank row** between the
   end of the disruption narrative and the start of the Decision Analysis
   block. A naive "read until blank row" parser will swallow the decision
   table as if it were more disruption fields. `read_kv_section` stops on
   `stop_contains=("Decision Analysis",)` to guard against this — keep that
   guard if you rewrite this function.
3. The "Decision Analysis Score" section sometimes has TWO header rows (one
   with full question text like "Cost impact — Does this decision save..." in
   a side column, one with short names like "Cost"/"Resilience Gain"
   immediately above the data). The code finds the real header row by looking
   for the row immediately before the first numeric data row, not by offset.
4. "Overall" score column is blank in 9 of 10 sheets (only FIB-001 has it
   filled in by hand). `compute_overall()` auto-fills it as the average of
   Cost/Resilience Gain/Feasibility/Speed/Sustainability when missing, and
   flags it with `_overall_calculated: true`.
5. `FIB-011`, `Sheet-013`, `FIB-014`, `FIB-015` are empty placeholder sheets
   for future case studies — `extract_case()` returns `None` for these
   (detected via empty "Use case ID") and `main()` skips them. Leave this
   behavior — the user chose "skip empty ones" over showing placeholders.
6. Sheet naming inconsistency: Master Directory lists a case as `FIB-013` but
   the actual tab is named `Sheet-013`. Not yet fixed in the source file —
   flag to the user if it matters for a future change, don't silently rename.
7. Column G near the disruption section has unused leftover template headers
   ("Problem (Root Cause)", "Proposed Solutions", etc.) with no data anywhere
   in the workbook — confirmed empty across all 10 sheets. Safe to ignore,
   don't try to extract from them.

## Data model (cases.json)

```
{
  "cases": [
    {
      "id": "FIB-001",
      "name": "...", "industry": "...", "brand_group": "...", "scale": "...",
      "normal_flow_nodes": [{"label": "Node 1 – ...", "description": "..."}],
      "normal_flow_steps": [{"step": 1, "process": "...", "node": "..."}],
      "kpis": [{"label": "Cost", "value": "..."}],              // free-text values, not numeric
      "disruption": [{"label": "Trigger event", "value": "..."}],
      "decision_blocks": [
        {"source": "Decision Analysis by the Company: Nokia",
         "decisions": [{"Decision No": "1", "Description": "...", "Action": "...",
                        "Cost": "Low", "Risk": "Reduced", ..., "Best when": "..."}]}
      ],
      "decisions_impact_summary": [{"label": "D1 ...", "Cost": "Low", ...}],
      "kpi_change_summary": [{"label": "Normal (pre-fire)", "<metric>": "...", ...}],
      "decision_scores": [{"label": "...", "Cost": 4, "Resilience Gain": 4, ..., "Overall": 4.0}],
      "sources": ["citation text", ...]
    }
  ]
}
```
Field names inside `decisions`/`kpi_change_summary` rows are NOT fixed across
cases (see "what legitimately varies" above) — always iterate keys
dynamically in dashboard code, never destructure a fixed set of fields.

## Dashboard (src/App.jsx)

Single React component (dark "case file / incident dossier" visual
theme — coral accent for risk/disruption, teal for resolution/recovery).
Two views: list (search + industry filter + card grid) and detail (tabbed:
Overview / Normal operations / Disruption / Decisions / Outcome). No external
dependencies beyond React itself. `import DATA from "./data/cases.json"` at
the top is a normal static ES import — Vite bundles it at build time, so
there's still no runtime `fetch()` of case data, just no more manual
placeholder-substitution step to get there (see "Producing a standalone
artifact" above).

`ratingTone()` color-codes rating chips (good/bad/neutral/warn) using
keyword heuristics on free-text values like "Low"/"Very High"/"Reduced" —
this is a first-pass heuristic, not perfectly reliable in every metric
context (e.g. "High" is good for Quality but bad for Cost). Worth revisiting
if it reads wrong for a specific case.

## Decisions already made with the user (don't re-litigate without reason)

- Dashboard purpose: browse/explore case studies (not a heavy analytics/BI tool).
- Excel restructuring: light cleanup only, keep one sheet per case — no full
  relational rebuild.
- Empty placeholder sheets: skip them silently, don't show "coming soon" cards.
- Data refresh: NOT live/automatic — re-run extraction manually whenever the
  user shares an updated Excel file.
- Tooling: migrated from a hand-rolled Python string-replace build step to a
  real Vite + React dev environment (`npm run dev`/`build`). `dashboard_template.jsx`
  was renamed `src/App.jsx` and now imports `cases.json` as a normal ES
  module instead of a `__CASES_JSON__` placeholder; `dashboard_built.jsx` is
  gone, replaced by `dist/index.html` from `npm run build` (self-contained
  via `vite-plugin-singlefile`, still gitignored/not committed).
