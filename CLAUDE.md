# Future Industry in a Box — supply chain case-study dashboard

## What this project is

A browsable library of real-world supply chain case studies — **21 cases**
(`FIB-001`..`FIB-021`) covering both disruptions (something broke, a response
was needed — chip fires, cyberattacks, recalls, blockages, geopolitical
single-source risk, etc.) and improvements (a proactive change — RFID
rollouts, vertical integration, digital ops). Source of truth is a
hand-authored Excel workbook, one sheet per case. This is qualitative
narrative + some numeric scoring, not transactional data (no SKUs/inventory/
orders). Each case can be explored as a step-by-step guided walkthrough, and
a subset of cases additionally have a hand-drawn 12-panel comic.

## Project layout

Real Vite + React project — `npm install`, `npm run dev`, `npm run build`.

```
data/
  source.xlsx          <- the original workbook (replace this when the user sends an update)
scripts/
  extract.py            <- Excel -> JSON extraction engine (label-anchored, see below)
public/
  comics/
    FIB-001/1.png .. 12.png   <- one folder per case that has comic artwork, see below
    FIB-002/ ...
src/
  data/
    cases.json           <- extracted data, regenerated by scripts/extract.py — don't hand-edit (see Comics below)
  App.jsx                <- the whole app: components, data mapping, and a `CSS` template-literal of styles
  main.jsx               <- React DOM mount point
index.html               <- Vite entry HTML
vite.config.js            <- React plugin + vite-plugin-singlefile (see below)
package.json
```

### Dev workflow

```
npm install       # once, or after dependency changes
npm run dev        # local dev server with HMR at localhost:5173
npm run build       # production build -> dist/index.html
npm run preview      # serve the production build locally to sanity-check it
npm run extract       # re-run the Excel -> JSON extraction (python3 scripts/extract.py data/source.xlsx src/data/cases.json)
```

`npm run extract` requires `openpyxl` (`pip install openpyxl`) — not a node
dependency, it's a standalone Python script.

To rebuild after the Excel changes, just run `npm run extract` — `src/App.jsx`
imports `src/data/cases.json` as an ES module, so Vite picks up the new data
on the next `dev`/`build` automatically.

### Producing a standalone artifact (e.g. for Claude Artifacts)

`npm run build` uses `vite-plugin-singlefile` (configured in `vite.config.js`),
which inlines all JS/CSS into `dist/index.html` instead of emitting separate
hashed asset files. `cases.json` gets bundled into that inlined JS at build
time — there is no runtime fetch of it. `dist/` is gitignored — regenerate it
with `npm run build` whenever you need it, don't commit it.

Note: comic artwork (`public/comics/`) is **not** inlined by
`vite-plugin-singlefile` — Vite copies `public/` as separate static files, and
a single-file artifact build would reference them as absolute paths
(`/comics/FIB-001/1.png`) that won't resolve outside this app's own server.
A standalone artifact export is fine for the walkthrough/data parts of a case
but won't show comic art unless that's addressed separately.

## Comics — folder convention, auto-detected (don't hand-edit `comic` into cases.json)

Comic artwork lives at `public/comics/<case id>/<panel number>.<ext>`, e.g.
`public/comics/FIB-001/1.png` .. `12.png`. Vite serves `public/` as-is, so
that's reachable at `/comics/FIB-001/1.png` in the browser.

**To add a comic for a case: just drop its folder in, named exactly after the
case id, with panels numbered from 1, then run `npm run extract`.** `extract.py`'s
`find_comic()` scans `public/comics/<id>/` for files matching `<n>.(png|jpg|jpeg)`
and — if any exist — writes `case["comic"] = {"dir": "/comics/<id>", "count": <max n found>, "ext": "<ext>"}`
into that case automatically. No manual JSON editing, and it's safe to re-run
extraction any time — the comic field is re-derived from disk every time, not
clobbered by it. (This used to be a landmine: the `comic` field was hand-typed
into `cases.json` for FIB-001..007, which meant any re-extraction would
silently wipe it since `source.xlsx` has no column for it. Fixed — don't
reintroduce manual edits to this field.)

A case with no comic folder has no `comic` key at all, and `App.jsx`'s
`ComicMode` falls back to auto-generated placeholder "cards" built from the
case's own data (flow nodes, trigger, decisions, best-rated outcome) so the
comic tab still works before artwork exists — see `generatedPanels()` and
`buildComic()` in `App.jsx`.

## Why the extraction works the way it does (read this before touching extract.py)

Each case sheet is a **narrative document, not a table**. Row positions are
NOT fixed and shift per sheet. There is no reliable coordinate system — only
label text is reliable. **Never hardcode a row number.**

### Header fields (read by label, column C next to the label in column B, rows 1-15):
`Use case ID`, `Use case Name`, `Industry Verticle`, `Brand & Group`,
`Nature of usecase` (→ `nature`, drives the Disruption/Improvement branch
below), `Scale`.

### Baseline flow
`Baseline Operations (Normal Flow)` heading, then node label/description pairs
in columns B/C until a blank row (`normal_flow_nodes`). Separately, a `Step`
table with columns Step/Process/Node right after it (`normal_flow_steps`) —
these are two different representations of the same flow, both kept.

### Normal KPI conditions
Generic label→value pairs after `Normal KPI Conditions` — KPI names are NOT
fixed (Ryanair tracks "Load factor", Toyota tracks "Sub-tier supplier
visibility", etc.), read dynamically, never destructure a fixed field list.

### Disruption vs improvement
`case["nature"]` picks the branch: a `Disruption details` section is read for
disruption cases, an `Integration details` section for improvement cases.
Only four labels are kept from the disruption section even if more exist in
the sheet — `trigger event`, `root cause details`, `affected nodes`,
`effect on supply chain` (see `DISRUPTION_ALLOWED_LABELS` in `extract.py`).
No such whitelist currently exists for `improvement` — if that section starts
picking up noise, that's the place to add one.

### Decision tables — found generically, not by a fixed count or label list
`find_all_decision_table_anchors()` scans the **entire sheet** for any cell
reading "Decision No" or "Decision" (not just column B), merges adjacent
"Decision"/"Decision" header rows, and for each anchor found, looks up to 6
rows above it (`nearest_title_above`) for a title. That title decides what
kind of block it is:
- title contains "impact summary" → parsed as a generic table into
  `decisions_impact_summary` (rows keyed `decision_no`, see gotcha below)
- title contains "score" → parsed the same way into `decision_scores`, then
  `compute_overall()` fills in a missing `Overall`/`Overall...` column as the
  average of whichever of Cost/Resilience Gain/Feasibility/Speed/Sustainability
  are numeric, flagged `_overall_calculated: true`
- anything else → a decision block (`decision_blocks`), one entry per
  decision column, keyed by whatever row labels exist (`Description`,
  `Action`, rating columns, `Best when`, ...)

This means the number of decision blocks per sheet, and the column position
of each, both fall out of the scan automatically — nothing hardcoded.

### Known tolerances baked into the row-walkers (don't remove these):
- `read_kv_section` / `read_generic_table` / `read_decision_block` all stop
  after **two consecutive blank rows** (`blank_streak >= 2`), not one — some
  sheets have a single blank row inside a section that isn't the end of it.
- Several readers take a `stop_contains` list (e.g. `("Decision Analysis",)`)
  so they bail out the moment they see the start of the next section, even
  with no blank row separating them.
- `validate_case()` + `main()`'s end-of-run report flag cases missing header
  fields, missing disruption/improvement details, missing KPIs, missing
  decisions, or decisions with no matching impact-summary row — check this
  output after any extraction, it currently flags FIB-020 and FIB-021 as
  missing disruption details.

### ⚠️ Known bug, not yet fixed — mismatched key name
`decisions_impact_summary` and `decision_scores` rows are extracted with
`label_key="decision_no"` (so each row looks like `{"decision_no": 1, "Cost":
"Low", ...}`), but `App.jsx`'s `ImpactTable` and `ScoreRanking` both still
read `row.label` / `s.label` for the name shown in the first column / next to
the bar. Since neither table actually has a `label` key anymore, **every
decision name in the Impact summary table and the Scored ranking list
currently renders blank**. Confirmed by inspecting real extracted
`cases.json` — not a hypothetical. Fix is either: extract.py writes both
`decision_no` and a `label` (e.g. `f"D{decision_no}"` or pulled from the
matching decision's `Description`), or `App.jsx` reads `decision_no` instead
of `label`. Flagged to the user, not fixed as of this writing — don't assume
it's fine just because nothing throws.

## Data model (cases.json)

```
{
  "cases": [
    {
      "id": "FIB-001", "name": "...", "industry": "...", "brand_group": "...",
      "nature": "Disruption",            // or "Improvement" — drives UI branching
      "scale": "...",
      "comic": {"dir": "/comics/FIB-001", "count": 12, "ext": "png"},  // only present if public/comics/<id>/ exists
      "normal_flow_nodes": [{"label": "Node 1 – ...", "description": "..."}],
      "normal_flow_steps": [{"step": 1, "process": "...", "node": "..."}],
      "kpis": [{"label": "Cost", "value": "..."}],
      "disruption": [{"label": "Trigger event", "value": "..."}],   // disruption cases
      "improvement": [{"label": "...", "value": "..."}],             // improvement cases
      "decision_blocks": [
        {"source": "Decision Analysis by the Company",
         "decisions": [{"decision_no": 1, "Description": "...", "Action": "...",
                        "Cost": "Low", "Risk": "Reduced", ..., "Best when": "..."}]}
      ],
      "decisions_impact_summary": [{"decision_no": 1, "Cost": "Low", ...}],  // no "label" key — see bug above
      "decision_scores": [{"decision_no": 1, "Cost": 4, ..., "Overall": 4.0}],
      "sources": ["citation text", ...],
      "_sheet_name": "FIB-001"
    }
  ],
  "errors": []   // sheets that threw during extraction, with the exception text
}
```
Field names inside `decisions` rows are NOT fixed across cases — always
iterate keys dynamically, never destructure a fixed set.

## App (src/App.jsx)

Branded "Future Industry in a Box," light/colorful theme (all CSS is in the
`CSS` template literal at the bottom of the file, injected via `<style>`).

- **Grid view**: cards with an industry icon (see `VERTICALS` — 9 categories,
  each with color + icon + keyword matcher, extend by adding a row there),
  search, industry filter pills, and a Disruption/Improvement filter. Cards
  for cases with a comic get a small animated "Comic" bookmark ribbon
  (`ComicBookmark`/`hasComic()`).
- **Case detail**: a chooser screen offers two ways to explore a case:
  - **Guided walkthrough** (`GuidedMode`/`buildSteps`): cumulative step-by-step
    timeline (flow → KPIs → trigger/problem → a "what would you do?" prediction
    box before decisions are revealed → each decision → outcome). Notes typed
    into the prediction box are kept in React state only (`predictionNotes`
    in `App()`), not persisted.
  - **Comic** (`ComicMode`/`buildComic`): panel-by-panel reader with a
    full-screen lightbox, keyboard nav (←/→/O/Esc), and a whole-page 2×2
    overview. Falls back to generated placeholder panels when no artwork
    exists (see Comics section above).
  - Both end on a completion screen with prev/next case navigation.
- `ratingTone()`/`toneColor()` color-code rating chips (good/bad/neutral/warn)
  from free-text values like "Low"/"Very High"/"Reduced" — a heuristic, not
  perfectly reliable in every metric context (e.g. "High" is good for Quality
  but bad for Cost).

## Decisions already made with the user (don't re-litigate without reason)

- Dashboard purpose: browse/explore case studies (not a heavy analytics/BI tool).
- Excel restructuring: light cleanup only, keep one sheet per case — no full
  relational rebuild.
- Data refresh: NOT live/automatic — re-run `npm run extract` manually
  whenever the user shares an updated Excel file or adds a comic folder.
- Tooling: real Vite + React dev environment (`npm run dev`/`build`), not a
  hand-rolled build step. `vite-plugin-singlefile` makes `npm run build`'s
  output a single self-contained `dist/index.html` (comic images excepted,
  see above).
- Comics: folder-convention + auto-detection in `extract.py`, not hand-edited
  JSON — see Comics section. Case id must match the folder name exactly
  (`FIB-001`, case-sensitive), panels numbered from 1.
